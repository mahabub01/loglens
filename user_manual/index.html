১. ভূমিকা ও আর্কিটেকচারাল মূলনীতি

LogLens কেন অনন্য এবং কীভাবে কাজ করে
Core Architecture

LogLens হলো লারাভেল ডেভেলপার ও ডেভঅপস ইঞ্জিনিয়ারদের জন্য তৈরি করা একটি রিয়েল-টাইম অ্যাপ্লিকেশন লগ অ্যানালাইজার এবং ফুল-স্ট্যাক পারফরম্যান্স মনিটরিং প্ল্যাটফর্ম। এটি Laravel 10, 11, 12, এবং 13 ভার্সনের সাথে শতভাগ কম্প্যাটিবল।

জিরো এক্সট্রা কুয়েরি

মনিটরিংয়ের জন্য অ্যাপ্লিকেশনের ডাটাবেসে কোনো বাড়তি SQL কুয়েরি চালানো হয় না। এটি সম্পূর্ণ প্যাসিভ ইভেন্ট লিসেনারের মাধ্যমে কাজ করে।

জিরো ডাটাবেস মাইগ্রেশন

আপনার অ্যাপ্লিকেশনের ডাটাবেসে কোনো টেবিল তৈরি করতে হয় না। সব মেট্রিক্স বাউন্ডেড মেমোরি বা অপশনাল রেডিসে জমা থাকে।

জিরো ফ্রন্টএন্ড বিল্ড টুল

Tailwind, Node, Vite বা npm বিল্ডের কোনো ঝামেলা নেই। এটি বিশুদ্ধ Blade, Bootstrap 5 এবং Font Awesome দিয়ে তৈরি।

মনে রাখবেন: ডিফল্টভাবে প্রোডাকশন নিরাপত্তার জন্য প্যাকেজটি বন্ধ থাকে (LOGLENS_ENABLED=false)। আপনার প্রজেক্টের .env ফাইলে LOGLENS_ENABLED=true সেট করলেই ড্যাশবোর্ডটি লাইভ হবে।

ল্যাটেন্সি পার্সেন্টাইল (p50, p95, p99) কেন জরুরি?

সাধারণ গড় (Average) অনেক সময় সঠিক চিত্র তুলে ধরে না। কারণ ১০০০টি ফাস্ট রিকোয়েস্টের মধ্যে ১টি খুব স্লো রিকোয়েস্ট থাকলে গড় মান বিকৃত হতে পারে।

  • Median (p50): ৫০% সাধারণ ইউজারের ক্ষেত্রে সাইট কত দ্রুত কাজ করছে।
  • p95 Latency: ৯৫% ইউজার এই সময়ের চেয়ে দ্রুত রেসপন্স পাচ্ছে। শুধুমাত্র টপ ৫% ইউজার এর চেয়ে বেশি সময় ব্যয় করছে।
  • p99 Latency: ৯৯% ইউজারের সন্তুষ্টির পরিমাপক। এটি অ্যাপ্লিকেশনের সবচেয়ে স্লো ১% প্রান্তিক রিকোয়েস্টকে নির্দেশ করে।
স্ট্যাটাস কোড ডিস্ট্রিবিউশন ও স্লো রুট টেবিল
  • 2xx, 3xx, 4xx, 5xx চার্ট: ট্রাফিকের মধ্যে কত শতাংশ সফল (2xx), কত শতাংশ রিডাইরেক্ট (3xx), কত শতাংশ ক্লায়েন্ট এরর (4xx), এবং কত শতাংশ সার্ভার ক্র্যাশ (5xx)।
  • Top Slow Routes Table: যেসব রুটের রেসপন্স টাইম কনফিগার করা থ্রেশহোল্ড (যেমন >500ms) অতিক্রম করে, সেগুলো স্বয়ংক্রিয়ভাবে এই টেবিলে চিহ্নিত হয়।

সিকিউর কুয়েরি নরমালাইজেশন ও বাইন্ডিংস মাস্কিং

নিরাপত্তার স্বার্থে ইউজারের পাসওয়ার্ড, টোকেন বা সেনসিটিভ তথ্য কখনোই মনিটরিং স্ক্রিনে প্রদর্শিত হয় না। প্রতিটি SQL স্টেটমেন্ট নরমালাইজ করে সংখ্যা ও স্ট্রিংকে ? দিয়ে রিপ্লেস করা হয়: 

-- আসল কুয়েরি:
SELECT * FROM users WHERE email = 'secret@user.com' AND role_id = 4;

-- LogLens নরমালাইজড ফিঙ্গারপ্রিন্ট:
SELECT * FROM `users` WHERE `email` = ? AND `role_id` = ?;
N+1 কুয়েরি হিওরিস্টিক অ্যালার্ট

যদি একই HTTP রিকোয়েস্টের ভেতর একই প্যাটার্নের কুয়েরি বারবার লুপ আকারে এক্সিকিউট হয় (যেমন: প্রতিটি ইউজারের প্রোফাইল আলাদা কুয়েরি দিয়ে ফেচ করা), তবে LogLens স্বয়ংক্রিয়ভাবে Potential N+1 Alert ফ্লাগ দেখাবে যাতে ডেভেলপাররা with() বা Eager Loading যোগ করতে পারেন।

৭. অ্যাপাচি mod_status লাইভ মনিটরিং (Apache Status)

রুট: /loglens/apache

https://your-domain.com/loglens/apache
স্ক্রিনশটটি বড় করে দেখতে ছবিতে ক্লিক করুন
লাইভ রেট ও ওয়ার্কার স্কোরবোর্ড
  • Requests Per Second (RPS): প্রতি সেকেন্ডে অ্যাপাচি কতগুলো নতুন রিকোয়েস্ট প্রসেস করছে।
  • Bytes Per Second (BPS): প্রতি সেকেন্ডে নেটওয়ার্ক দিয়ে কত কিলোবাইট ডেটা আদান-প্রদান হচ্ছে।
  • Worker Scoreboard: মোট কয়টি ওয়ার্কার বর্তমানে বিজি (Writing, Reading, KeepAlive) এবং কয়টি ওয়ার্কার আইডল (Waiting for connection) অবস্থায় প্রস্তুত আছে।
ব্যাকগ্রাউন্ড ডেমন চালুর কমান্ড:
টার্মিনালে রান করুন: php artisan loglens:apache-collect (অথবা Supervisor দিয়ে ব্যাকগ্রাউন্ড প্রসেস হিসেবে চালু রাখুন)।

  • Docker Cgroups v1 & v2: যদি অ্যাপটি ডকার কন্টেইনারে চলে, তবে কন্টেইনারের জন্য নির্ধারিত আসল মেমোরি সিলিং ট্র্যাক করে।

৪-স্তরের ডেস্ট্রাক্টিভ সুরক্ষা চেইন
  1. কনফিগারেশন গেট: config/loglens.php-তে 'allow_destructive_actions' => true না থাকলে ব্যাকএন্ড স্বয়ংক্রিয়ভাবে রিকোয়েস্ট ব্লক করে দেবে (403 Forbidden)।
  2. ডেস্ট্রাক্টিভ কলব্যাক অথোরাইজেশন: সাধারণ অ্যাডমিন দেখতে পারলেও ডিলিট করতে পারবে কি না তার জন্য আলাদা গেট LogLens::destructiveAuth(...) পাস করতে হবে।
  3. CSRF প্রোটেকশন: সমস্ত স্টেট-চেঞ্জিং এন্ডপয়েন্টে লারাভেলের ভ্যালিড CSRF টোকেন বাধ্যতামূলক।
  4. UI টু-স্টেপ কনফার্মেশন: মোডালে থাকা "I understand this action is irreversible" চেকবক্সে টিক না দেওয়া পর্যন্ত লাল রঙের "Yes, Clear File" বাটনটি ডিজেবল থাকবে।
সতর্কবার্তা: লগ ফাইল ক্লিয়ার করলে ফাইলের ভেতরের তথ্য মুছে 0 Bytes হয়ে যায়। এটি রিকভার করা সম্ভব নয়। প্রোডাকশনে সর্বদা ডেস্ট্রাক্টিভ অ্যাকশন শুধুমাত্র সুপার অ্যাডমিনের জন্য অনুমোদিত রাখুন।

১২. .env কনফিগারেশন চেকলিস্ট ও রেফারেন্স

Cheat Sheet

আপনার প্রোজেক্টের .env ফাইলে নিচের ভেরিয়েবলগুলো দিয়ে প্রতিটি মডিউল আলাদাভাবে কন্ট্রোল করা যায়:

# ==========================================
# LogLens Master Switch & Configuration
# ==========================================
LOGLENS_ENABLED=true
LOGLENS_PATH=loglens

# Monitoring Modules Toggle
LOGLENS_DB_MONITORING=true
LOGLENS_HTTP_MONITORING=true
LOGLENS_APACHE_MONITORING=false
LOGLENS_SYSTEM_MONITORING=true
LOGLENS_QUEUE_MONITORING=true
LOGLENS_SCHEDULER_MONITORING=true
LOGLENS_ALERTS_ENABLED=true

# Security & Destructive Actions
LOGLENS_ALLOW_DESTRUCTIVE=false

# Thresholds
LOGLENS_SLOW_REQUEST_THRESHOLD_MS=1000
LOGLENS_SLOW_QUERY_THRESHOLD_MS=500
LOGLENS_LONG_RUNNING_JOB_THRESHOLD_MS=5000
AppServiceProvider-এ অ্যাক্সেস রেস্ট্রিকশন কোড
use MehrabHossain\LogLens\Facades\LogLens;

public function boot(): void
{
    // ড্যাশবোর্ড দেখার অনুমতি (Read Only)
    LogLens::auth(function ($request) {
        return app()->environment('local') ||
               in_array($request->user()?->email, [
                   'admin@yourdomain.com',
                   'devops@yourdomain.com',
               ]);
    });

    // লগ ফাইল মোছার অনুমতি (Destructive Action)
    LogLens::destructiveAuth(function ($request) {
        return in_array($request->user()?->email, [
            'lead-architect@yourdomain.com',
        ]);
    });
}
